# Flash-Ticket 프로젝트 작동 방식 분석

## 1. 개요

이 프로젝트는 실시간 티켓 예매 시스템 데모입니다. 사용자가 웹 화면에서 티켓을 구매(선점)하고 결제하는 과정을 시뮬레이션합니다. 

주요 특징은 다음과 같습니다:
- **실시간 업데이트**: 웹소켓(WebSocket)을 사용하여 다른 사용자의 구매/결제 현황이 모든 접속자에게 실시간으로 공유됩니다.
- **컨테이너 기반 실행**: Docker와 Docker Compose를 통해 백엔드와 데이터베이스 환경을 안정적으로 구축하고 실행합니다.
- **관심사 분리**: 프론트엔드와 백엔드가 명확히 분리되어 있으며, 각각 최신 기술 스택(React, FastAPI)을 사용합니다.

## 3. 컴포넌트 상세

### 가. 프론트엔드 (`flash-tickets-web` 디렉토리)
- **역할**: 사용자 인터페이스(UI)를 제공하고, 사용자의 입력을 받아 백엔드와 통신합니다.
- **기술**: React, TypeScript, Vite (개발 서버 및 빌드 도구)
- **주요 기능**:
  - 남은 수량, 판매 완료, 선점(Hold)된 티켓 수를 실시간으로 표시합니다.
  - 백엔드의 WebSocket(`_ws`)에 연결하여 재고 변동 이벤트를 수신하고 화면을 업데이트합니다.
  - '구매', '결제' 버튼 클릭 시 백엔드의 HTTP API(`_purchase`, `_pay_`)를 호출하여 서버에 작업을 요청합니다.
  - 초기 연결 실패 시, 백엔드 서버가 준비될 때까지 자동으로 재연결을 시도하는 로직이 구현되어 있습니다.

### 나. 백엔드 (`app` 디렉토리)
- **역할**: 핵심 비즈니스 로직을 처리하고, 데이터베이스와 상호작용하며, 프론트엔드에 API를 제공합니다.
- **기술**: Python, FastAPI, Uvicorn (ASGI 서버), SQLAlchemy (ORM), `asyncpg` (비동기 DB 드라이버)
- **주요 기능**:
  - **HTTP API**: `/purchase` (티켓 선점), `/pay/{order_id}` (결제 완료) 등의 엔드포인트를 제공합니다.
  - **WebSocket API**: `/ws` 엔드포인트를 통해 연결된 모든 클라이언트에게 재고 변동(`stock.update`)과 같은 실시간 이벤트를 방송(broadcast)합니다.
  - **백그라운드 작업**: `main.py`의 `expire_task` 함수가 주기적으로 실행되며, 결제 시간이 만료된 '선점' 상태의 주문을 '만료' 처리합니다.
  - **데이터베이스 초기화**: `docker-compose` 실행 시, `init_db.py` 스크립트가 자동으로 실행되어 필요한 테이블을 생성하고 초기 데이터를 삽입합니다.

### 다. 데이터베이스
- **역할**: 모든 상태(이벤트, 주문, 재고 등)를 영구적으로 저장합니다.
- **기술**: PostgreSQL
- **주요 테이블**: `events` (총 티켓 수, 판매된 수량), `orders` (주문 정보), `holds` (선점 정보 및 만료 시간)

## 4. 실행 흐름

이 프로젝트는 다음 단계로 실행됩니다.

1.  **프론트엔드 의존성 설치**: `flash-tickets-web` 디렉토리에서 `npm install`을 실행합니다.
2.  **프론트엔드 서버 시작**: `flash-tickets-web` 디렉토리에서 `npm run dev`를 실행하여 `localhost:5173`에서 개발 서버를 시작합니다.
3.  **백엔드 & DB 시작**: 프로젝트 루트 디렉토리에서 `docker-compose up -d`를 실행합니다. 이 명령은 다음을 수행합니다.
    - `postgres` 컨테이너를 시작하여 PostgreSQL 데이터베이스를 실행합니다.
    - `api` 컨테이너를 빌드하고 시작합니다.
    - `api` 컨테이너가 시작될 때, `docker-compose.yaml`에 정의된 `command`에 따라 `python -m app.init_db`를 먼저 실행하여 DB를 초기화한 후, `uvicorn`으로 FastAPI 서버를 실행합니다.
4.  **애플리케이션 접속**: 사용자는 `http://localhost:5173`에 접속하여 애플리케이션을 사용합니다.

## 5. 핵심 동작 원리

### 가. 티켓 구매 및 결제 흐름
1.  **선점 (Hold)**: 사용자가 '구매' 버튼을 클릭합니다.
    - 프론트엔드는 백엔드의 `/purchase` API를 호출합니다.
    - 백엔드는 재고를 확인하고, `orders` 테이블에 'HOLD' 상태의 주문을 생성하며, `holds` 테이블에 만료 시간이 있는 선점 정보를 기록합니다. 
    - 이 변경 사항을 모든 클라이언트에게 웹소켓으로 전송하여 '남은 수량'과 '홀드 중'인 수량을 업데이트합니다.
2.  **결제 (Paid)**: 사용자가 '결제' 버튼을 클릭합니다.
    - 프론트엔드는 백엔드의 `/pay/{order_id}` API를 호출합니다.
    - 백엔드는 `orders`의 상태를 'PAID'로 변경하고, `events` 테이블의 `sold_qty`를 증가시키며, `holds` 테이블의 선점 정보를 삭제합니다.
    - 이 변경 사항 또한 모든 클라이언트에게 웹소켓으로 전송하여 '남은 수량'과 '판매 완료' 수량을 업데이트합니다.

### 나. 실시간 재고 업데이트
- 프론트엔드 앱이 실행되면 백엔드의 `/ws` 엔드포인트에 웹소켓 연결을 시도합니다.
- 백엔드에서 재고에 변동을 주는 모든 작업(구매, 결제, 선점 만료)이 발생하면, 연결된 모든 웹소켓 클라이언트에게 변경된 재고 정보를 담은 `stock.update` 메시지를 전송합니다.
- 프론트엔드는 이 메시지를 수신하여 화면의 숫자들을 즉시 업데이트합니다.
