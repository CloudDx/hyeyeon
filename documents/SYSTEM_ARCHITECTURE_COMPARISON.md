#  Flash Tickets - 시스템 아키텍처 비교

##  현재 아키텍처 (Before)

```
 사용자들 (1000명 동시 접속)
    │
    ▼
 Load Balancer
    │
    ▼  
Nginx Proxy
    │
    ▼
 FastAPI (단일 인스턴스) ←  병목 지점!
    │
    ├──  재고 조회 (50ms) ──────────┐
    │                              │
    ├──  PostgreSQL 락 대기 ─────────┤
    │                              │
    ├──  이메일 발송 (500ms) ─────────┤ 모든 작업이
    │                              │ 동기적으로 실행
    ├──  WebSocket 브로드캐스트 ─────┤ = 응답 지연
    │                              │
    └──  메트릭 수집 ──────────────────┘
    │
    ▼
 PostgreSQL (과부하 상태)
    │
    ▼
 사용자 응답 (800ms 소요) ```

** 문제점:**
- 모든 요청이 DB 직행 → **50ms씩 대기**
- 동기 처리로 **800ms 응답시간**  
- 단일 인스턴스 → **확장 불가**
- DB 과부하 → **병목 현상**

##  구매 프로세스 상세 플로우

### 1. 사용자가 "2장 구매" 클릭

```
 사용자A (2장 구매 요청)
    │ POST /purchase (qty=2, eventId=1)
    ▼
 Nginx: 로드밸런싱
    │ 
    ▼
 FastAPI-2 선택됨
    │
    ▼ 1ms
 Redis: 분산 락 획득 
    │ LOCK "purchase:event1" (동시성 제어)
    ▼ 1ms  
 Redis: 재고 확인
    │ GET "stock:event1" → {remaining: 50, sold: 50}
    ▼  충분한 재고!
 Redis: 재고 차감 (캐시 업데이트)
    │ DECRBY "stock:event1:remaining" 2 → 48장
    │ INCRBY "stock:event1:sold" 2 → 52장
    ▼ 1ms
 PostgreSQL: 주문 데이터 저장
    │ INSERT INTO orders (id, qty, status='HOLD')
    │ INSERT INTO holds (expires_at=now()+300sec)
    ▼ 30ms
 RabbitMQ: 이벤트 발행 (비동기)
    │ publish("purchase.completed", {orderId, eventId, qty})
    ▼ 1ms
 사용자A ← "주문 완료!" (총 34ms 소요!) ```

    ├──────────────┬──────────────┬──────────────┬──────────────┐
    │              │              │              │              │
    ▼              ▼              ▼              ▼              ▼

   Worker         Worker         Worker        Worker         Worker
    │              │              │              │              │
    ▼              ▼              ▼              ▼              ▼

   "48장 남음!"     (500ms)       (100ms)       (200ms)        (1000ms)

 사용자는 이미 응답받음! 백그라운드에서 비동기 처리중...
```

##  핵심 구성 요소 설명

###  Redis (메모리 캐시)
- **역할**: 재고 데이터 캐싱, 분산 락, 세션 관리
- **효과**: 50ms → 2ms (DB 접근 최소화)
- **특징**: 메모리 기반 초고속 데이터 저장

###  RabbitMQ (메시지 큐)
- **역할**: 비동기 작업 처리, 이벤트 기반 아키텍처
- **효과**: 즉시 응답 + 백그라운드 처리
- **특징**: 안정적인 메시지 전달 보장

###  PostgreSQL (영구 저장소)
- **역할**: 주문 데이터, 결제 정보 영구 저장
- **효과**: ACID 트랜잭션 보장
- **특징**: 데이터 일관성과 무결성 유지

>  **핵심**: Redis로 속도 UP, RabbitMQ로 확장성 UP, 장애 시 Fallback으로 안정성 보장!
